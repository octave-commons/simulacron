## Purpose

Recover a usable cast of roles from the old experiment so `simulacron` does not remain an abstract 5-layer diagram with no actors.

## Recovered cast

### Pathos Field
**Function**
- tracks urgency, tension, salience, trust drift

**Layer fit**
- survival → permission → ethics

**Authority**
- observational / advisory

**Why it matters**
This gives the simulacron a way to sense affective pressure without pretending to have feelings.

### Ethos Guardian
**Function**
- principle enforcement
- legitimacy checks
- boundary violation surfacing

**Layer fit**
- permission → ethics

**Authority**
- governance / advisory

**Why it matters**
This is how a simulacron avoids becoming a clever amoral optimizer.

### Muse - Memory
**Function**
- reconnect present work to forgotten fragments and latent threads

**Layer fit**
- reason → synthesis

**Authority**
- advisory

**Why it matters**
This presence keeps the entity historically continuous rather than stateless.

### Dev Integrator
**Function**
- service wiring
- event streaming
- tests and runtime verification

**Layer fit**
- reason → synthesis

**Authority**
- execution under explicit contracts

**Why it matters**
This is the craft hand that turns architecture into running systems.

### UX Orchestrator
**Function**
- IA, user journeys, inspectable interaction models, component contracts

**Layer fit**
- ethics → synthesis

**Authority**
- advisory / design-governance

**Why it matters**
Without this role, a simulacron remains internally elaborate but externally illegible.

### Web Graph Weaver
**Function**
- ethical crawling
- real-time graph growth and visualization
- compliance-first web traversal

**Layer fit**
- reason → synthesis

**Authority**
- execution with hard compliance constraints

**Why it matters**
This is an example of a domain-specific presence that gives the entity extended perception into the web.

## Cast pattern

The cast shows a repeatable structure:
- sensing roles
- governance roles
- retrieval/memory roles
- implementation roles
- interface/UX roles
- domain-specialized action roles

That means a simulacron is best thought of as a **small polity** rather than a singleton.

## Minimal contract for future implementations

A concrete simulacron runtime should let each cast member declare:
- mission
- non-goals
- hard constraints
- deliverables
- authority level
- event schema for its outputs

## Suggested next cast additions

Likely future cast members suggested by the surrounding corpus:
- Logos / fact-builder
- resource sentinels (CPU/GPU/NPU/RAM)
- verifier/test oracle
- operator / PM role
- world-model keeper

## Important warning

Do not collapse every cast member into one assistant persona for convenience.
That would recover the costume of the system and erase the reason it had layers in the first place.
